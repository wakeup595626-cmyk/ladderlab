# LadderLab 工程文件生成指南（给 AI 看）

这份文档是给 AI 助手（Codex、Claude、Cursor 等）读的说明书。目标只有一个：把一段中文的
课程设计题目，变成一份**能导入、能编译、能在仿真里跑对、能导出图片、还能生成分享链接**
的 `.ladderlab.json`。

判断你有没有做对，不看描述像不像，看仓库自带的校验命令有没有打印 ✔：

```bash
node scripts/check-project.mjs examples/你的题目.ladderlab.json
```

命令都在仓库根目录执行。第一次用先 `npm install`（Node 22.12 或更高版本）装依赖，
否则会提示找不到校验器需要的模块。

## 三条铁律

1. **只输出 JSON，不输出解释。** 需要解释的部分放在 JSON 之外的对话里。
2. **变量必须先声明再使用。** 触点、线圈里出现的每个名字，都必须在 `tags` 里有一条定义，
   或者是一个已声明的定时器/计数器实例的 `.Q` 位（如 `T1.Q`）。
3. **每个程序段只有一个输出。** 一个 `rung` = 一条串联主干 = 一个 `output`。
   需要多个输出就拆成多个程序段。

## 文件结构

```jsonc
{
  "schema": 1,              // 固定写 1
  "name": "八路流水灯",      // 工程名，可以中文，最多 64 字
  "profile": "v21",         // "v14" 或 "v21"；只有 v21 支持 TONR
  "tags": [ ... ],          // 变量表
  "rungs": [ ... ]          // 程序段
}
```

## 变量（tags）

```jsonc
{
  "id": "t-start",          // 必填。全文件唯一，自己起名，建议 t-xxx
  "name": "Start",          // 必填。梯形图上显示的名字，字母/数字/下划线，不能数字开头
  "address": "%I0.0",       // 必填。地址，见下方约定
  "kind": "BOOL",           // 必填。"BOOL" 或 "INT"
  "initial": false,         // 必填。BOOL 只能 true/false；INT 只能是 -32768~32767 的整数
  "comment": "启动开关",     // 必填。中文注释，显示在变量表里（可以为空字符串）
  "bitOf": "LampByte"       // 可选。作为某个 INT 字节变量的一位，写那个变量的 name
}
```

`name` 最长 64 字符，`comment` 最长 500 字符，`address` 最长 32 字符。

地址写法：`%<区域><字节>.<位>` 表示位，`%<区域><B|W|D><字节>` 表示字节/字/双字。
区域只能是 `I`（输入）、`Q`（输出）、`M`（内部存储），位只能 0~7。

课程作业建议按下面的范围分配，读题的人一眼能对上真实 PLC 的接线：

- 输入 `%I0.0` ~ `%I1.7`
- 内部存储 `%M0.0` ~ `%M99.7`
- 输出 `%Q0.0` ~ `%Q1.7`
- 字节/字 `%MB10`、`%MW10`、`%MD10`

模拟器本身不禁止更大的字节号，但超出上表范围会让报告和实物接线对不上。同一区域里，
**任何两个变量的地址范围不能重叠**：`%MW10` 已经占用了第 10、11 字节，就不要再声明
`%M10.0` 或 `%MW11`。

位别名（`bitOf`）用于把 8 个指示灯塞进一个字节变量：`LampByte` 用 `%MB10`，
则 `Lamp1` 用 `%M10.0`、`Lamp2` 用 `%M10.1`，依此类推，且必须和所属字节同字节。

## 程序段（rungs）

```jsonc
{
  "id": "r1",               // 必填。全文件唯一
  "label": "正转自锁与互锁",   // 必填。这个程序段在做什么，中文一句话，最多 120 字
  "nodes": [ ... ],          // 必填。串联条件，从电源侧向输出侧排列
  "output": { ... }          // 必填。唯一的输出
}
```

节点只有两种：

```jsonc
// 触点
{ "type": "contact", "id": "c1", "kind": "NO", "tag": "Start" }

// 并联支路（每个 branch 是一条串联链）
{
  "type": "parallel",
  "id": "p1",
  "branches": [
    [ { "type": "contact", "id": "c3", "kind": "NO", "tag": "SB_Forward" },
      { "type": "contact", "id": "c4", "kind": "NC", "tag": "KM_Reverse" } ],
    [ { "type": "contact", "id": "c5", "kind": "NO", "tag": "KM_Forward" } ]
  ]
}
```

触点的全部字段：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `type` | 是 | 固定 `"contact"` |
| `id` | 是 | 全文件唯一 |
| `kind` | 是 | `NO` 常开、`NC` 常闭、`P` 上升沿、`N` 下降沿、`CMP` 比较 |
| `tag` | 是 | `NO/NC/P/N` 要 BOOL 变量；`CMP` 要 INT 变量或计数器实例的 `.CV` |
| `compare` | `CMP` 必填 | `{ "op": ">=", "value": 5 }`，`op` 只能是 `==` `<>` `>` `>=` `<` `<=` |

注意：**比较触点右边必须是常量**，不支持「两个变量比大小」。要比两个变量，先在一个程序段里
用 `SUB` 求差，再对差值做 `CMP`。

## 输出（output）

```jsonc
{ "id": "o1", "kind": "COIL", "tag": "KM_Forward" }
{ "id": "o4", "kind": "TON",  "tag": "T1", "pt": 500 }
{ "id": "o5", "kind": "CTU",  "tag": "C1", "pv": 5, "resetTag": "Reset",
  "qTag": "BinFull", "valueTag": "Count" }
{ "id": "o6", "kind": "MOVE", "tag": "LampByte", "sourceTag": "Count" }
{ "id": "o8", "kind": "PATTERN", "tag": "LampByte", "pulseTag": "Tick", "pattern": [1, 3, 7, 15] }
```

| kind | 含义 | 必填字段 | 可选字段 |
| --- | --- | --- | --- |
| `COIL` | 普通线圈，能流断则灭 | `tag`（BOOL 变量） | — |
| `SET` / `RESET` | 置位 / 复位，保持 | `tag`（BOOL 变量） | — |
| `TON` / `TOF` | 通电延时 / 断电延时 | `tag` 是**实例名**，`pt` 毫秒 | `qTag`（BOOL 状态）、`valueTag`（INT 已计时间 ET） |
| `TONR` | 保持型延时，仅 v21 | `tag` 实例名，`pt` | `resetTag`（BOOL 复位）、`qTag`、`valueTag` |
| `CTU` | 加计数 | `tag` 实例名，`pv` 预设值 | `resetTag`（BOOL 复位）、`qTag`（BOOL 满值）、`valueTag`（INT 当前值） |
| `MOVE` | 整数传送 | `tag` 目标 INT、`sourceTag` 或 `value` | — |
| `ADD` / `SUB` | 整数加减 | `tag` 目标 INT、`valueTag` 或 `value` | — |
| `SHL` / `ROL` | 左移 / 循环左移 | `tag` 目标 INT、`value` 移几位 | `valueTag` 用变量作移位次数 |
| `PATTERN` | 教学用灯字序列 | `tag` 目标 INT、`pulseTag` BOOL 推进脉冲、`pattern` 灯字数组 | `stepTag`（INT 当前步号） |

操作数优先级（写错这里最容易「编译过但算错」）：

- `MOVE`：认 `sourceTag`。同时写了 `value` 也只取 `sourceTag`。
- `ADD/SUB/SHL/ROL`：认 `valueTag`。同时写了 `value` 也只取 `valueTag`。
- 两者都是「变量优先、常量兜底」：不写变量引用时，才读 `value` 常量。
- 整数常量范围 `-32768 ~ 32767`；`PATTERN` 每个灯字范围 `0 ~ 255`。

定时器/计数器的实例名（如 `T1`、`C1`）**不写进 `tags`**，但必须满足两条：全局不重名，
且不能和任何变量同名字。读取它的状态用触点 `{ "kind": "NO", "tag": "T1.Q" }`；
计数器当前值既能用 `valueTag` 引出去，也能直接写 `"Count" 的 `CMP` 触点
`{ "kind": "CMP", "tag": "C1.CV", "compare": { "op": ">=", "value": 3 } }`。

## 编译器的硬性限制

写之前先记住这些，能省掉一半返工：

- `pt` 必须是 1~32767 的整数（毫秒）。超过 32 秒请级联两个定时器，或改用计数器。
- `pv` 必须是 1~32767 的整数。
- 同一个变量被多个线圈/输出连续驱动时，只有扫描顺序靠后的那个生效——编译器会警告
  「被多个线圈驱动」。需要交替通断就改用 `SET` / `RESET` 配对。
- 变量名不能重复，地址不能重叠。
- 变量上限 1000、程序段上限 1000、节点上限 5000、并联嵌套 32 层、`PATTERN` 灯字
  1024 个、导入文件 5 MB。

## 推荐的生成步骤

1. 先读题目，输出一张 I/O 表给人看：输入几个、输出几个、内部存储几个，每个叫什么、干什么。
2. 判断它是不是内置实验之一（抢答器、定时计数、交通灯、三层电梯、音乐喷泉、装配流水线）。
   是的话优先复用 `src/engine/courseLabs.ts` 里的现成实现，不要重写。
3. 不是的话，先写状态转换表（几个状态、转移条件、每个状态的输出），再转成程序段。
4. 每个程序段给一句中文 `label`，让人能对上题目里的动作。
5. 输出完整 JSON，保存成 `.ladderlab.json`。
6. **跑校验，必须看到 ✔ 再往下走：**

   ```bash
   node scripts/check-project.mjs examples/你的题目.ladderlab.json
   ```

   有错就按它给的「位置」和「改法」逐条改，改完重跑，直到 ✔。不要整份重写。
7. 校验通过后，再用仿真确认逻辑对（见下一节），最后生成分享链接。

### 这一步到底校验了什么

`check-project.mjs` 不复制任何规则，它通过 Vite 直接加载网页导入用的那份源码
（`src/lib/io.ts` 和 `src/engine/compile.ts`），所以 CLI、测试、页面三边永远同一套判定。
一次运行会走完四道关：

1. **导入**：JSON 语法、字段类型、结构上限、地址格式、变量名合法性。
2. **编译**：变量引用是否存在、BOOL/INT 类型是否匹配、实例名是否冲突、PT/PV 范围、
   双线圈等。错误（error）会让退出码变成 1，警告（warning）只提示。
3. **导出**：跑一遍导出前的序列化守卫，确认这份工程不会「能导入、却存不回去」。
4. **分享链接**：真实压缩一次，报告链接长度；超过 12000 字符会提示改用文件发送。

退出码 0 = 全部通过，1 = 有错误。所以 Agent 可以直接用退出码判断，不必人肉读输出。
加 `--json` 拿到机器可读结果，加 `--url` 在通过时顺带打印分享链接。

**编译通过 ≠ 逻辑正确。** 编译只证明「这张图能画出来、引用都合法」，不证明「按题目要求动」。
交付前至少手动推演一遍：初始状态该灭的输出是不是灭的、按启动后该动的动没动、到计数/到时间
后动作对不对、复位后状态有没有回到该回的地方。仓库里的
`src/lib/aiExampleBehavior.test.ts` 就是这种「真的按按钮」的验收写法，可以照抄结构。

## 参考样例

`examples/` 下有四个可以直接导入的完整工程，不确定怎么写就照骨架改，比从零开始稳：

- `motor-forward-reverse.ladderlab.json`：电机正反转，自锁加互锁。
- `running-light.ladderlab.json`：八路流水灯，定时器节拍加循环移位。
- `two-motor-sequence.ladderlab.json`：两台电机顺序启动、逆序停止。
- `pipeline-sorting.ladderlab.json`：流水线计数分拣，计数器 + 比较 + 满箱快照 + 换箱复位。
  这份是「课程设计级」的完整例子：12 个变量、7 段程序，带 `CTU` 的 `qTag/valueTag`、
  边沿触发、`CMP` 分流、`MOVE` 快照。

## 常见编译错误 → 怎么改

| 报错里出现 | 真实原因 | 怎么改 |
| --- | --- | --- |
| `不是有效的 JSON` / `Unexpected token` | 写了注释、尾逗号、中文引号或少了括号 | JSON 里不能有注释和尾逗号；用编辑器格式化一次再核对 |
| `schema 必须是 1` | 顶层少了或写错了 `schema` | 固定写 `"schema": 1` |
| `profile 必须是` | `profile` 不是 `v14`/`v21` | 只写这两个之一；用 `TONR` 就必须 `v21` |
| `变量名“X”不合法` | 用了中文、空格、连字符，或以数字开头 | 只用字母、数字、下划线 |
| `变量名“X”重复` | 同一个名字声明了两次 | 改名或删掉多余那条 |
| `地址重叠` | 两个变量占了同一个地址 | 每个变量独占地址；位别名要和所属字节同字节 |
| `触点引用了不存在的变量“X”` | 名字拼错，或忘了在 `tags` 里声明 | 补声明或改拼写；实例状态写 `T1.Q` |
| `触点“X”需要 BOOL 变量，当前类型是 INT` | INT 变量直接当普通触点用了 | 要判断数值就用 `CMP` 触点 |
| `变量“X”被多个线圈驱动…` | 同一变量在两段里都被 COIL 驱动 | 改成一段 COIL + 另一段 `SET/RESET`，或合并逻辑 |
| `PT 必须是 1～32767` | `pt` 是 0、负数、小数或超过 32767 | 改成整数毫秒；长延时级联定时器 |
| `PV 必须是 1～32767` | `pv` 越界或不是整数 | 改成 1~32767 的整数 |
| `CTU 缺少实例名` | `tag` 留空 | 实例名填 `C1` 这类名字，且不能和变量重名 |
| `MOVE 需要操作数变量或常量` | 既没写 `sourceTag` 也没写 `value` | `MOVE` 用 `sourceTag`，算术指令用 `valueTag` |
| `PATTERN 的每个灯字都必须是 0～255` | 灯字数组里混进了负数或大数 | 每个灯字改成 0~255 的整数 |

## 给用户一条链接（推荐交付方式）

**先跑出 ✔，再生成链接。** `share-link.mjs` 默认会先校验一遍，校验不过就直接失败，
不会给你一条打不开工程的好看链接：

```bash
node scripts/share-link.mjs examples/我的工程.ladderlab.json
```

它会打印一条 `https://wakeup595626-cmyk.github.io/ladderlab/#p=1.…` 的地址。
整份工程就在 `#` 后面（压缩过），不经过任何服务器。用户点开后页面会先问一句
「导入分享的工程「…」？」，点「导入」才会替换当前内容，点「先不导入」什么都不会变。

注意事项：

- 用户自己也能生成链接：网页右上角「导出 → 复制分享链接」。所以你不方便跑脚本时，
  可以让他先把工程导进网页，再自己复制一条链接转发。
- 链接超过 12000 字符时，微信、QQ 可能发不出去，改用文件导入。
- 确实需要跳过校验（比如只想先看看链接多长）时加 `--no-check`，但别拿它交付。
- 如果你根本跑不了 `node`（只在网页里对话、没有文件系统），就跳过脚本，
  把完整 JSON 放进代码块交给用户：他点网页顶部「导入」，展开
  「没有文件？直接粘贴工程 JSON」，粘贴后点「导入并打开」，效果一样。
- 片段里的内容是压缩数据，不要手工改动其中任何字符，改一个字符就打不开。
- 自测时可以加 `--site http://127.0.0.1:5173/` 指向本地开发服务器。
- `npm run qa:share` 会用真实浏览器验证弹窗、取消、导入、坏链接四种情况。

### 同学拿到链接后怎么出图

把这三步一并告诉用户，不要只说「你导出一下」：

1. 点开链接，弹窗问「导入分享的工程「…」？」时点「导入」。
2. 先看页面上有没有红色错误提示；有就先别导出，把报错原文发回来。
3. 点右上角「导出」→「图片格式」选 PNG（要矢量就选 SVG）→ 点「纯梯形图」。
   要连标题、变量表和 I/O 分配一起交，就点「完整程序」。

图片在当前浏览器里生成，不需要登录，也不会上传工程内容。

## 交付前检查清单

- [ ] `node scripts/check-project.mjs <你的文件>` 输出 ✔，退出码 0
- [ ] 每个程序段的 `label` 都能对上题目里的一个动作
- [ ] I/O 表里的每个输入、输出变量在程序里真的被用到了
- [ ] 至少推演过一遍：启动 → 过程 → 到点动作 → 复位/停止
- [ ] 分享链接能打开，且页面上显示的图和你给的一致

没勾完不要说「做好了」或「验证过了」。

## 这个项目不能做什么

- 不生成 TIA Portal 的 `.ap21` 工程，也不生成 SCL / FBD / HMI 或可再导入的
  SFC 源文件。
- 能导出顺序功能图 SVG / PNG，但那只是从当前梯形图归纳出的参考图；联锁、延时和
  扫描细节仍以梯形图为准，不能当成 TIA Portal 的 SFC 工程提交。
- 不连接真实 PLC，不能下载程序。
- 生成的图可以用在课设报告里，但不能当成博途的工程文件提交。
