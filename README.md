# LadderLab / 梯形实验室

在浏览器里编写、运行和观察 PLC 梯形图的教学仿真器。

![LadderLab 工作台](docs/screenshot.png)

LadderLab 面向 PLC 入门课程、实验预习和个人练习。它把梯形图编辑、变量表、编译诊断和
逐周期仿真放进同一个网页，打开即可使用，不需要安装博途或连接真实 PLC。

> LadderLab 是独立的教学项目，不是西门子产品或官方替代品，也不兼容 TIA Portal /
> SIMATIC S7 的工程文件、专有指令和硬件配置。项目中的“V14 / V21 档案”仅表示本仿真器
> 所开放的基础指令子集，方便课堂对照不同版本的练习，不代表完整复刻对应软件。

## 为什么不是“网页版博途”

完整复刻 TIA Portal 会涉及大量专有工程格式、授权软件、硬件驱动和未公开语义，既不适合
作为开源个人项目，也无法保证行为一致。LadderLab 选择把范围收窄到一个可验证的核心：

- 用梯形图表达常见的启保停、互锁、定时和计数逻辑；
- 在浏览器内执行可重复的离线扫描仿真；
- 用颜色、计时值和计数器值直接展示扫描结果；
- 用纯 TypeScript 引擎和自动化测试固定语义，方便长期维护。

这是一个可以逐步长大的教学平台，“几乎和博途一样”的承诺既不诚实，也没有必要。

## 已实现

- 梯形图梯级编辑：串联触点、并联分支、线圈、置位/复位和指令盒；
- V14 / V21 指令档案切换，并对当前档案不支持的指令给出编译诊断；
- 浏览器内离线仿真：扫描周期、边沿检测、TON / TOF / TONR、CTU；
- 在线监视：触点、并联支路、线圈、指令输出和运行时数值实时高亮；
- 变量表：BOOL / INT 变量、地址、初始值、注释与引用检查；
- 工程诊断：未绑定变量、类型错误、重复实例、多个线圈驱动等问题；
- 撤销/重做、自动本地保存、JSON 工程导入/导出；
- 内置启保停、顺序启动、计数包装、闪烁回路和边沿计数示例；
- 纯静态前端，适合直接部署到 GitHub Pages。

## 快速开始

需要 Node.js 22 或更高版本。

```bash
npm install
npm run dev
```

打开终端显示的本地地址即可。生产构建：

```bash
npm run build
npm run preview
```

常用检查：

```bash
npm test
npm run typecheck
npm run lint
```

## 部署到 GitHub Pages

仓库已经包含 GitHub Actions 的检查和静态站点部署流程。首次上传后：

1. 确认默认分支为 `main`；
2. 在 GitHub 仓库的 **Settings → Pages → Build and deployment** 中将 Source 选为
   **GitHub Actions**；
3. 推送 `main` 分支，等待 **Deploy to GitHub Pages** 工作流完成。

部署地址会显示在工作流的 deploy 步骤中。应用是纯静态前端，不需要数据库或后端服务。

## 第一次使用

1. 从左侧示例库载入“启保停”，或新建一个空白工程。
2. 在变量表中把输入、输出变量改成适合自己实验的名称。
3. 点击触点或输出，在右侧属性面板中修改变量、指令类型和参数。
4. 点击“运行”，然后在 I/O 面板中切换输入信号，观察绿色通电状态。
5. 使用“单步”逐个扫描周期观察逻辑，使用“复位”回到初始状态。
6. 工程会自动保存在当前浏览器；需要备份或换设备时导出 JSON 文件。

所有工程数据都保存在浏览器本地。清除站点数据会移除自动保存内容，请及时导出重要工程。

## 版本档案

版本档案只限制“本仿真器开放哪些指令”，不是对西门子软件版本的兼容性声明。

| 能力 | V14 档案 | V21 档案 |
| --- | --- | --- |
| 常开 / 常闭触点 | 支持 | 支持 |
| 上升沿 / 下降沿触点 | — | 支持 |
| 比较触点 | — | 支持 |
| 线圈 / SET / RESET | 支持 | 支持 |
| TON / TOF | 支持 | 支持 |
| TONR 累计定时器 | — | 支持 |
| CTU 计数器 | 支持 | 支持 |

切换档案不会自动删除现有逻辑；如果工程使用了新档案不支持的指令，诊断面板会标出问题。

## 仿真语义

LadderLab 按从上到下的顺序执行梯级，每个扫描周期执行以下步骤：

1. 对每个梯级计算触点与并联分支的能流；
2. 立即写入线圈、置位/复位、定时器和计数器的输出；
3. 更新边沿存储、计时值和计数值；
4. 进入下一扫描周期。

因此，前一个梯级在当前扫描写入的变量可以被后面的梯级读到；同一个 BOOL 变量被多个
普通线圈驱动时，扫描顺序靠后的输出会覆盖前面的结果。这些行为会在诊断中给出提示。

仿真周期由界面调度，不是硬实时 PLC。定时器和扫描时间适合教学观察，不应作为现场控制
或安全评估的依据。

## 工程结构

```text
src/
  engine/       纯 TypeScript 编译与扫描仿真引擎
  state/        不可变工程编辑操作
  components/   梯形图画布、工具栏、属性面板等界面
  lib/          JSON 导入导出、本地存储、ID 工具
  App.tsx       应用状态、仿真调度和界面组合
```

引擎不依赖 React，任何逻辑语义都应优先放进 `src/engine` 并用测试覆盖；界面只负责编辑、
展示和调度。

## 路线图

- v0.1：稳定的梯级编辑、V14/V21 档案、离线扫描仿真和本地保存；
- v0.2：更自然的拖拽/键盘编辑、只读分享链接、工程模板；
- v0.3：练习题与自动判分，适合课堂和实验课使用；
- v0.4：更多 IEC 风格指令、时序图和仿真轨迹导出；
- 后续评估 Modbus / OPC UA 等外部接口的教学模拟，不冒充真实安全控制器。

路线图是方向而不是已完成承诺。实现新指令时，应同时补充扫描语义测试和档案可用性测试。

## 当前限制

- 不导入或导出 TIA Portal、SIMATIC S7 工程文件；
- 不支持 SCL、SFC、FBD、HMI 组态或完整博途指令集；
- 不与真实 PLC 通信，不提供硬件下载、在线诊断或安全功能；
- 不模拟完整的 IEC 61131-3 运行时、浮点精度、扫描任务和通信协议；
- v0.1 使用结构化的梯级编辑器，不是完全自由的拖拽画布。
